# 0002 — 天候備案做成「路線上的決策點」，不做「出門前二選一」

- 狀態：**採用**
- 日期：2026-09-12

## 脈絡

9/17–23 的預報是全期間多雲、降雨機率 40–60%、最高 29–32°C。查證後確認**沒有颱風**（2026 年 24 号已於 9/7 轉為熱帶低壓），型態是**秋の長雨** —— 隨時可能下、但不是整天暴雨。

kyoto-plan（前一個 demo）處理不確定性的方式是 [ADR 0002 的「夜間雙軌 A／B ＋ 18:15 決策點」](../../../kyoto-plan/docs/adr/0002-two-track-evening.md)，那是針對「看不看得到 20:00 的主秀」這種**單一時點**的取捨。

這次不一樣：不確定的是**整整七天的天氣**，而且其中兩天完全沒有口譯陪同 ——
使用者對兩位讀者的描述是「**容易因為不熟悉焦慮，怕自己沒準備什麼**」。

## 決策

**不採用「出門前選 A 案或 B 案」的結構。** 改為：

1. 每一天同時備妥**戶外錨點**與**室內錨點**，當天視天候調換先後順序，而不是取消整日。
2. 需要真正二選一的那一天（9/18 鞍馬〜貴船），把決策點**放在路線上的一個實體位置** —— **貴船口駅的月台** —— 而且兩個分支之後會**合流到同一個下午**（一乗寺・恵文社）。

9/18 的具體形狀：

```
出町柳 08:30 発（同一班車，上車時不必決定）
   ↓
貴船口駅 08:58  ← 決策點：抬頭看天
   ├ 乾 → 不下車，再坐一站到鞍馬，翻山 100 分／2.5km
   └ 濕 → 就地下車，京都バス 33 上貴船，只走平緩鋪面路
   ↓ 兩者合流
一乗寺（恵文社，11:00–19:00，室內）
```

## 理由

「出門前二選一」有三個問題，而且三個都落在「人在異地、手上只有一支手機」的那一刻：

1. **決策時刻錯了。** 早上 07:30 在民宿看窗外，對三小時後山上的天氣沒有預測力。真正有資訊的時刻是人已經到了貴船口、站在那裡抬頭看天的那一秒。
2. **它要求提前變更。** 如果 A、B 兩案的車票、下車站、下午安排都不同，選錯就得整個重排 ——
   而「在陌生的地方臨時重排一整天」正是最會讓人焦慮的事。
3. **它會讓一整天報銷。** 秋の長雨的實況是「早上下、中午停」。用整日粒度取消，會為了一場兩小時的雨丟掉一整天。

把決策點釘在路線上，這三個問題同時消失：**兩個分支共用同一班車、同一張票、同一個下午**，
所以「選擇」退化成「要不要在這一站下車」—— 一個只需要抬頭看天的動作，不需要重排任何東西。

## 取捨

- **放棄**：事前確定性。使用者無法在出發前就知道 9/18 到底會走哪條路線，也因此無法預訂貴船的餐廳。
- **換得**：備案不需要任何事前變更，而且決策發生在資訊最完整的時刻。

順帶解決了川床的問題：貴船的川床料理**店家自己會在雨天中止營業**（ひろ文 受付 11:00–13:00，5/1〜9月末），所以它本來就無法預訂進一個有雨天分支的行程。與其為它硬做一套備案，不如把它整個移除 —— 這也是使用者的判斷（「好像還好不用誒而且好貴」）。

## 後果

- 攻略頁需要一個專屬的 UI 元件（`fork`）來表達「地點 ＋ 兩條分支 ＋ 合流點」，而不是把備案寫在注意事項裡。
- 凡是攻略頁上寫「視情況」而沒有指名地點的地方，都代表設計沒做完。
- **大文字山被刪除**，因為它無法套用這個結構：它的價值 100% 在展望，雲霧就等於零，沒有「換順序」可言，只有「去或不去」。濕滑的花崗岩碎石下坡也讓它在雨天不只是降級、而是危險。

## 追記（店家調査のあとで見つかった穴）

この構造には**最初の版で見落としがあった**：**濡れ側の分岐は 10:30 に終わってしまう**。
貴船神社の本宮〜結社〜奧宮は往復 40 分しかないので、
09:05 に着いた場合、次の予定（一乗寺）まで**約 4 時間の空白**ができる。

乾き側（鞍馬を越える）は 100 分の山越えがあるので 14:00 に一乗寺へ着く。
つまり「両分岐は同じ午後に合流する」という設計は、**時刻まで合流するとは限らない**。

濡れ側にだけ **詩仙堂（¥700）と 圓光寺（¥500）** を足して埋めた。
選定理由はこの ADR の原則そのもの：**どちらも座敷から庭を眺める形式**なので、
雨は減点ではなく加点になる。一乗寺駅から徒歩 10–15 分、二軒は互いに 3 分。

**教訓**：分岐を作ったら、**両方の所要時間を別々に積算する**。
合流点が同じでも、そこに着く時刻が同じとは限らない。
