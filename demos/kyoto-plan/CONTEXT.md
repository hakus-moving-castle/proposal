## 交付物形態

**PWA**
攻略頁為 PWA（`manifest.webmanifest` + `sw.js` + icons），可加入手機主畫面、離線開啟。
圖示為 Gemini 產生的狐狸圓形 logo（`logo-source.jpeg`，僅存本機、不進版控）。
裁切方式：以**圓環十字掃描**求出真正圓心 (1166, 853) 與直徑 976，
再裁成 1162px 方形（logo 佔畫面 84%，確保 Android maskable 圓形遮罩不切到圓環）。
→ 若要重裁，**不要用整體 dark-pixel bbox** —— 右下的雲會把 bbox 撐大，圓心會偏。
**Service Worker 只在 HTTPS 下生效** —— 雙擊本機檔案（`file://`）不會註冊，
需透過 GitHub Pages 網址才能安裝與離線使用。

**QR 內嵌（Inlined QR）**
兩張 QR 以 data URI 內嵌於 `index.html`，不走外部檔案。
理由：改札前若圖檔載不出來，整張票就失效 —— 內嵌讓 SW 快取 index.html 即等於快取票券。

**放大用 QR 的處理與驗證**
從票券圖精確裁出 QR 本體（x107–193, y40–126，87×87px，不含任何文字），
補 5 模組（15px）純白靜空區，最近鄰整數倍放大 6× 至 702px。
以 CoreImage `CIDetector` 解碼驗證，處理前後 payload 一致，並自 `index.html` 反向抽出再驗一次。
→ **任何再次改動 QR 圖像，都必須重新解碼驗證。**

**為何指定京都河原町上車**
1. **阪急京都線的起站** —— 排隊就一定有座位。走了一整天，座位優先於少走幾步

## 存取控制

**密碼閘（Password Gate）**
密碼 `0920`。輸入後寫入 `localStorage['kyoto-plan-pw']`，同一裝置不再詢問（不設失效）。

**實作方式不是「遮住畫面」，而是真的加密**：
兩張 QR 的 PNG 以密碼導出的 keystream（FNV-1a 種子 + xorshift32）XOR 加密後 base64 內嵌，
另存明文的 FNV-32 校驗值。密碼正確才解得出、校驗才通過。
→ **看原始碼也拿不到 QR。** 不用 WebCrypto，故 `file://`、離線、舊瀏覽器皆可用。

**這道鎖擋得住什麼、擋不住什麼**
- ✅ 擋得住：只知道網址的人、搜尋引擎（另加 `robots: noindex,nofollow`）
- ❌ 擋不住：**4 位數密碼可被暴力破解（僅一萬種）**。真要提高強度就換長一點的密碼
- ❌ 擋不住：頁面的**行程文字仍在原始碼中**（只有 QR 被加密）
- ⚠️ repo 為 **PUBLIC** —— 這是這道鎖存在的原因

## 登入畫面的背景演出

密碼畫面的背景把「水族館 → 百鬼夜行」整天的跨度畫出來，
**刻意做少數幾個大尺度元素**（初版做了 11 個小元素，太瑣碎）：

| 元素 | 尺寸 | 週期 | 來自 |
|---|---|---|---|
| 巨大なクラゲ | 280px，緩慢上昇＋左右搖擺 | 46s / 12s | 京都水族館（クラゲワンダー） |
| 水の波紋 ×2 | 擴散至 820px | 16s（錯開 8s） | 水族館 |
| 百鬼夜行の行列 | 高約 114px，一團橫越 | 46s | 太秦映画村 |
| 青海波 | 高 180px，緩慢平移 | 38s | logo 的波紋呼應 |

行列的三個妖怪：**唐傘小僧**（一目一足の傘）、**ろくろ首**、
**提灯を持つ狐**（走在最前頭）。
→ 狐は站上 logo 的呼應，且「狐火・狐の嫁入り」本就屬日本妖怪譜系。
→ **不要用西洋萬聖節式的圓身波浪底幽靈** —— 初版用過，調性不對。

**狐の作図で踏んだ罠（再修正時の注意）**
1. 鼻先を細長い針にすると鳥のくちばしに見える → **短く厚い楔形**にする
2. 尾の内縁を体の輪郭より外側で止めると、間に**背景色の隙間**が出る
   → 内縁は体（背側 x≈32–38）に**重ねる**
3. 尾を横に膨らませると丸い球になる → **縦に伸ばして先を細く**、尻から上へ跳ね上げる
4. 提灯は竿の横に置くと浮く → **横木を付けて吊り下げる**
5. 腕は竿まで**届かせる**（途中で止めると宙に浮いた棒に見える）
6. 尾先の白い斑点は小さすぎて光の汚れに見えた → 入れない

> 小さい表示・低不透明度のままでは形の崩れが判定できない。
> 検証時は `.gate-box` / 他レイヤーを `display:none` にし、
> `.parade` を `width:230%; opacity:1; animation:none` にして拡大して見る。

**狐の作図で効いた手法**
- **頭と両耳を一本のパスで描く** → 耳と頭の隙間・耳間の谷間が構造的に発生しない
- 尾は体に**重ねたまま**、境目に紙色の細い線（幅1.5・不透明度.38）を**継ぎ目として引く**
  → 隙間を作らずに「体と尾を分ける」。パスを離すと必ず背景色が漏れる
- 口は鼻先まで届かせない（先端まで引くと嘴が割れて見える）


全部 `aria-hidden` + `pointer-events:none`，`prefers-reduced-motion` 下整層 `display:none`。

## 時間軸の点 — 位置合わせで踏んだ罠

**症状**：空心の丸が進行線から右に約 1px ずれ、中に入れた実心の点も
さらに 0.5px ずれる。3回直しても直らなかった。

**原因は2つ重なっていた**

1. **擬似要素に `box-sizing:border-box` は効かない**
   `*{box-sizing:border-box}` の `*` は `::before` / `::after` に一致しないため、
   これらは `content-box`。border は width の外側に付く。
2. **`border:1.5px` はデバイスピクセルに吸着して 1px になる**
   結果 painted 幅が 9+1+1 = **11px（奇数）** になり中心が半端な位置に来る。
   4px（偶数）の内側の点はそこに中心を合わせられない。

**解**：`border:1px` / `width:10px` にして painted 12px（偶数）にする。
中心が整数に乗り、内側の点と揃う。

**検証方法の教訓**
`getComputedStyle` の `borderWidth` は **1.5px を 1px と報告する**ため、
それを使った計算は必ず 0.5px 狂う。
→ **同じ値で実 div を作り `getBoundingClientRect()` で painted box を測る。**
擬似要素には rect が無いので、この代理測定が唯一信頼できる。

## 夜のいろ（ダークモード）

**切り替えの規則**：`17:00〜06:00` なら夜。**時刻だけで決める。**

> 当初 `OS が dark || 時刻` にしていたが、端末を常時ダークにしていると
> OS 条件が常に真になり、朝でも夜モードになってしまった（実機で発生）。
> 「時刻で切り替える」という要件に対して OS 設定に拒否権を持たせてはいけない。
> `prefers-color-scheme` はもう見ていない（診断パネルに表示はするが未使用）。

17:00 は映画村の入村時刻。行程が夜に入る瞬間に、攻略ページ自身も夜になる。
`?theme=night` / `?theme=day` で上書きできる（確認用）。
FOUC を避けるため `<head>` の早い段階で判定し、以後は 1 分ごと・
復帰時・OS 設定変更時に追従する。

**QR の全画面だけは、どちらのテーマでも白のまま。**
読み取り機は高コントラストの白地を要る。`#qr-ov` 配下は変数を一切使わず
色を直書きしてあるので、構造的にテーマの影響を受けない。**ここは凝らない。**

**擬似要素・SVG の「抜き」は必ず `var(--paper)` を使う**
妖怪や狐の目は暗い剪影に開けた穴。夜は剪影が明るくなるので、
目の色も背景に追随しないと消える。`fill="#FAF8F3"` のような直書きは不可。
→ `style="fill:var(--paper)"` で指定する（SVG の presentation attribute は
`var()` を解釈しないため、attribute ではなく style で書く）。

**光りものは夜に強める**：提灯の box-shadow、円相の stroke。
明るい地では光暈はほとんど読めないので、淡色時の値のままだと夜に物足りない。

## 入村券を iframe で埋め込まない

**技術的には可能だが、壊れる。** 実測:
- `X-Frame-Options` も CSP `frame-ancestors` も無い → 埋め込み自体は拒否されない
- しかし `set-cookie: session=…; Path=/; Secure; HttpOnly` ―― **SameSite 属性が無い**
  → ブラウザは既定で `SameSite=Lax` として扱う
  → **クロスサイトの iframe には cookie が送られない**ため、券のページが
    セッションを維持できない可能性が高い

加えて非技術的な理由:
- **スタッフが操作する画面**なので、本物のドメイン上の本物の券の画面を
  見せるべき。他人のページに包まれていると相手が躊躇する理由になる
- 失敗した時の場所が入村口。成功しても遷移が一回減るだけで、割に合わない

→ `target="_blank"` で本物のページを開く。**改札の前で凝らない。**
（QR の全画面を白のままにしているのと同じ判断。）

## 提灯の光暈が切れていた（夜だけ見える不具合）

**症状**：夜モードで、hero の提灯の光暈の下半分が水平に切れる。
「次のセクションの色に隠れている」ように見える。

**原因**：`header{overflow:hidden}` による切り取り。
`box-shadow: 0 0 26px 10px` は要素の外側へ **spread 10 + blur 26 ≒ 36px**
広がるが、提灯から header 下端までは 16px しか無かった。
昼は光暈が淡くて切り口が見えず、夜に強めたことで露出した。

**解**：提灯の見た目の位置を動かさずに余地だけ作る。
`header` の `padding-bottom` と `.proc` の `bottom` を**同じ量（26px）増やす**
→ 提灯の絶対位置と区切り線との間隔（28px）は不変、
  光暈の余地だけ 16px → 42px になる。

> **教訓**：`overflow:hidden` の容器の中で `box-shadow` を使う時は、
> spread + blur のぶんの余地を内側に確保する。
> 光暈を強めた時は、切り取りの有無を必ず確認する。

## アイコンは付けない（2026-09-06 検討）

見出しの横に絵文字やアイコンを付けて内容を一目で分かるようにする案を検討したが、
**やらない**と判断した。

**理由1：文字と重複している。** 11個の見出しすべてが、すでに語で類別を言っている
（バス停・待ち合わせ／市バス／水族館／**イルカ**／徒歩・JR／**昼食**／商店街／
Cafe／JR／映画村／決めます）。「イルカのがっこう」の横にイルカの絵を置くのは
同じことを二度言うだけ。

**理由2：調性を壊す。** 明朝体と低彩度の紙色に対して、絵文字は彩度が高すぎる。
線画SVGなら色は合わせられるが、得られるのは結局重複した情報。

**すでに一目で分かる層が2つある**
- 節の**点の色**：水色＝水族館の時間帯／土色＝午後／藤色＝夜／小さい灰＝移動
- **タグ**：屋内・そば専門・全部アーケード・今日のいちばん など（排版だけで作れる）

→ 分類の合図が足りない時は**アイコンではなくタグを増やす**。
実際この検討で、店を鶴屋万艸に差し替えた際に
「今日のいちばん」というタグが失われていたことに気づき、そちらを戻した。

## 時刻の書き方（2026-09-06 に確定）

> **時刻は「だいたい」で書く。分単位で釘を打たない。**
> **どこも 20〜30分の余裕をとる。遅れると困る所は、早着に振る。**

**分単位で書いたことが、そのままバグになっていた**
- 「12:30 出館 → 12:40 の電車」→ 駅まで**徒歩7分**なので余裕3分
- 「16:30 カフェを出る → 16:35 の電車」→ 駅まで**徒歩7分**なので**マイナス2分**（接続不能）

固定の分を書くと、こちらの引き算ミスがそのまま相手の遅刻になる。
しかも各区間には Google Maps の「ルートを見る」（transit 深層リンク）があり、
**実際の時刻はそちらのほうが正確**。だから固定の時刻表は書かない。

**書き換えた形**
- 節の時刻はすべて「**〜ごろ**」
- 電車・バスは**本数だけ**（「10〜15分に1本」「だいたい15分に1本」）
- 実際の時刻は「ルートを見る」に委ねる
- 「時刻はぜんぶだいたいです。急ぐ必要はありません」を節の頭に明記

**唯一の硬い制約だけを強調する**
**水族館の入場 10:30〜11:00。** ここだけは遅れると券が無効。
逆に **17:00 の入村は締切ではない**（券は21:00まで有効）ので、
遅れても困らないと明記した。急がせないため。

**確保できた緩衝（実測の所要時間との差）**
```
集合 → バス            10分（バスは10分に1本）
水族館 着 → 入場        10分（意図的な早着）
12:15 出発 → 昼食      14分
昼食 → 商店街            3分（戻る7分。締切ではない）
16:15 出発 → 入村      17分（かつ17:00は締切ではない）
```

## 読んだ時の感じ方（2026-09-06 に確定）

ハクの実際の考え：
> 行程は列挙してあるだけ。どこかに長くいたくなっても、急に寄り道したくなっても
> 問題ない。**ぜんぶ行く必要はない。**
> 普段の自分の旅行も大まかな方向だけ決めて、その場で決めている。
> **これだけ調べたのは「はじめて会う日だから、当日に困らないように」でしかない。**

**問題**：ページは全部「だいたい」に直したあとでも、
垂直の時間軸＋11の節という**構造そのもの**が「これが今日の流れです」と読ませる。
「急がなくていい」とは書いてあったが、**「行かなくていい」とは書いていなかった。**
この2つは別のこと。

**入れたもの**
- hero、日付の下に一行：**「ぜんぶまわらなくて大丈夫な一日です」**
  （最初に目に入る位置で枠組みを決める）
- 「一日の流れ」の前書きを書き換え：
  - これは予定表ではなく**行き先の候補**
  - 長くいても、道にそれても、**まるごと飛ばしても大丈夫**
  - **はじめて会う日なので、当日に迷ったり困ったりしないぶんだけ調べた**
    ← この理由を本人に見せることで、文書の意味が
      「彼が私の一日を決めた」から「私が困らないようにしてくれた」に変わる

> **これは事実の問題ではなく語り口の問題。**
> 内容が正確でも、読んだ時に管理されている感じがしたら失敗している。

## ボタンがくっついていた（2026-09-06 修正）

`.maps{gap:7px; margin-top:11px}` は**上マージンしか持たない**。
`details.note` の最後の子が `.maps` で、その直後に `.shop-act`（下マージンも上マージンも
持たない）が続くと、**隙間が実測 0px** になってピルが上下に密着する。

該当は昼食の「満席・お休みだったら」の1箇所だけ（ページ全体を走査して確認）。
→ `details.note > .maps:last-child{margin-bottom:11px}` で 0px → 11px。

**測り方**：`.maplink, a.tel` を全部取って、隣り合う要素の
`getBoundingClientRect()` の差を出し、10px 未満を洗い出す。
残るのは 7px のものだけ（同じ flex コンテナ内の折り返し ＝ `gap:7px` そのもの）で正常。
